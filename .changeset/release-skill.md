A new `/release` skill opens the release pull request from `dev` to the default branch. Asked for a pull request from `dev` to `main`, a session had to improvise it each time, once read the request as a change of the branch flow and once repeated test steps the shipped pull requests had already run. The skill releases the current repository, or every repository one level below a folder that is none whose `dev` is ahead, and a name such as `/release api` selects one. A script lists the merged pull requests whose merge commit `dev` ships and the issues they close. The body follows the repository's template, closes those issues, links every workflow or deploy the merge starts, and its test plan holds only what production shows for the first time. The user's GitHub App opens or updates the pull request, one repository after another.
