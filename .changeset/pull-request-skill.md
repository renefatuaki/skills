Add the pull-request skill. It opens every pull request as a draft without stopping, from a template with a summary, the linked issue, the automated coverage and a test plan of numbered steps the reviewer runs in the running application, with prerequisites per platform for iOS, web, API and CLI. It finds the issue in the prompt, the branch name and the commit trailers, takes label and milestone from it, lists every decision it took as an assumption, and offers the template with each pull request while the repository has none with a test plan. A branch that already has an open pull request gets its title and body revised in place from what they say, with a comment when a reviewer may already be testing. On the user's word it marks the draft ready, requests the named reviewer, sets the issue to In review in its project and hands the pull request to the pull-request-review skill when an agent can run a step of the test plan.
