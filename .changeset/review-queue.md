A pane docked on the right lists the open pull requests of the repository as links in the order to review them. A header row such as `renefatuaki/skills · 3 open` names the repository in bold and links to its pull requests, and the tab reads `Review queue · skills` while a second pane is open. Each row such as `3.   #42 Add the parser draft after #41` has the label indented by the chain it waits on. In the desktop app and on mobile the pane has its own layout, the repository as a heading with a caption such as `3 open · top to bottom`, and per row the position, one thin guide per pull request in the chain it waits on, a green dot for ready or a grey hollow dot and a dim `Draft` for a draft, the title cut at the width the surface draws and the number at the right edge, with the row under the pointer highlighted. A pull request comes after the one its base branch is the head branch of, and after the one that closes an issue blocking one of its own closing issues. Each stack is listed in one piece, depth first, and of two children the one with fewer pull requests after it comes first. Stacks among themselves go ready before draft, then the oldest. The pane opens when a session starts and after each refresh while pull requests are open, and closes when there are none. The list refreshes at a session start, on each prompt of a person and after a successful `gh pr` call in Bash, and `/review-queue` refreshes it and opens the pane by hand. Claude Code loads one hooks module per plugin, so `hooks.json` now names `module.mts`, which registers the progress band and the pane.
