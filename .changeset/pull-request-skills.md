Add the pull-request and pull-request-review skills. Every pull request opens as a draft from the template of the templates skill, with Summary, Diagram, Linked issue, Scope, Tradeoffs, Blast radius, Automated coverage and a test plan of numbered steps that the reviewer runs in the application, with prerequisites for iOS, web, API and CLI. The body follows technical-writing and stays under about 40 lines apart from the test plan. The skill finds the issue in the prompt, the branch name and the commit trailers, brings the diagrams a branch touches up to date and lists every decision it took as an assumption. The draft turns ready for review itself when every check passes, the test steps the agent can run pass, no assumption is open and nothing waits for the user. The ci-watcher agent waits for the checks, and loop-on-ci fixes a failed one. Otherwise the draft stays until the user calls it ready, and marking it ready requests the named reviewer and sets the issue to In review. pull-request-review checks out a pull request, starts the application through a `verify-<app>` skill when the repository holds one, runs the steps it can drive, hands the rest to the reviewer and posts the result with a row per step and the evidence of its own steps. A bundled script ticks the passed steps in the description. The approval stays the reviewer's own click, and pull-request-review is hidden from the model.
