The skills copied from pstack follow upstream `cursor/plugins` at `9580c23`. Four skills are new. `sharpen` rewrites a prompt so it asks for a deeper version of the task, and `in-your-own-words` restates the goal and the problem before any work. `create-formal-verification-skill` writes a project skill that proves one key property of the code with a model checker or another verifier, and `maintain-formal-verification-skill` brings that check back in line after the code changed. After its offer of a verification skill, `/setup-models` offers once to generate a formal verification skill. The `engineer` agent is a delegate of the session that runs `/engineering`, never the runner of a playbook. When several copies of the plugin are installed, it reads the newest. `reflect` never edits a skill in the plugin cache. It changes a skill of this plugin on a branch of the plugin's repository, with its own pull request. The principles fix-root-causes, test-behavior-not-implementation, attack-the-premise and make-operations-idempotent explain the idea instead of naming mechanisms, and seven skills lose sections that did not change what an agent does. `worktree-audit.sh` takes `-b <ref>` for the branch that pull requests merge into, and reads file times with GNU and BSD `stat`.
