# Upstream sources

Which outside text does this plugin carry, and how does it stay in sync with its source?

Parts of this plugin are copied word for word from other projects. This file names each source, the commit the copy is based on, every change made to fit Claude Code and this repository, and what was left out. Run `pnpm run check-upstream` to list what changed upstream since the recorded commit.

## Sources

| [Cursor Team Kit](https://github.com/cursor/plugins/tree/main/cursor-team-kit) by Cursor | `cursor-team-kit/` | MIT | `9580c23696ac8d7abed0c166f2f9918800afb819` |

Both sources live in the repository `cursor/plugins`. Upstream generates `harness/pstack/claude-code/` from `pstack/` and installs it as the Claude Code plugin `pstack`. Its text equals `pstack/` except for one line per skill that points to the [Claude Code adapter](https://github.com/cursor/plugins/blob/main/harness/pstack/claude-code/docs/harness/claude-code.md) (M29) and two links of the guide that point to GitHub. The adapter is not a source of content. Its tables show how each Cursor name reads in Claude Code. Where a table row differs from the mapping below, the mapping wins. The Files table tracks the adapter as a reference, so `check-upstream` reports a new name rule.

## How a copy is made

1. Take the upstream file at the base commit.
2. Replace each Cursor passage with its Claude Code wording. In text first copied at a base older than `9580c23`, take the wording of the Claude Code port of pstack where the port changed the same passage, such as transcript paths, model resolution and the `Skill` tool. In text that a later sync adds or rewrites, replace only each Cursor name with its Claude Code name from the adapter's tables. The Claude Code port was a fork of `cursor/plugins` and is no longer published.
3. Apply the mapping below.
4. Apply the cuts named in the file's row under [Files](#files).

Nothing else changes. Quoted text keeps its own style, even where this repository's writing rules differ.
